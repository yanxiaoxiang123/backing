## 用户可见行为

- 副驾驶未发送文字在关闭重开、切页、刷新和进入完整工作台后恢复；不会因导航产生提交，也不会将文字写入 URL。
- 优先按会话隔离；没有会话时按规范化股票隔离，无股票使用新研究草稿。副驾驶与完整工作台共用匹配身份的草稿。
- 已保存内容与主动清空都优先于 URL prompt、股票预填及晚到会话数据。点击欢迎问题仍可以填入输入框。
- 异步发送收到接收确认后才清空；创建失败、明确拒绝或运行时不可用均保留文字。首次创建成功但提交失败的草稿迁入已创建会话，刷新后可重试。
- 等待确认期间抑制重复提交；关闭重开副驾驶仍保持锁定。切换会话后，旧提交的完成不会清空另一个会话或后续修改的草稿。
- 恢复目标会话尚未加载成功时可以编辑草稿，但发送与 Enter 等待其加载成功。加载失败后可选择该会话重试，副驾驶可关闭重开重试。
- 普通 HTTP 环境缺少 crypto.randomUUID 时可以继续编辑和发送。存储受限时使用当前页面内存降级。

## 独立审查和修复

一次只读独立审查对比本轮开工前快照，避免把用户和前两轮修改混入审查。结论为无 Critical、两项 Important、无 Minor；两项均经回归复现后修复，没有再次派审查者。

1. 恢复中的会话已有草稿可显示，但加载对象仍为空，发送可能创建错误会话。新增副驾驶和工作台两个延迟/失败详情 GET 浏览器回归，先观察发送按钮错误启用，再实现身份恢复状态与发送保护；加载时可编辑，加载成功后只向目标会话提交。
2. 直接使用 UUID API 在普通 HTTP 环境报错；获取提交快照失败还可能遗留锁。新增存储及真实适配组件回归，先观察三项失败，再增加版本生成降级，并将快照获取移入 try/finally。缺少 UUID 时编辑、拒绝后重试、确认清空，以及异常后的锁释放均已验证。

故障注入测试会主动删除存储条目，后续断言只检查其应保证的锁释放与重新编辑重试，不声称被外部删除的存储仍可恢复。修复后全量单元/组件测试 277/277 通过。

## 实现方取舍和代价

以下为实现判断，不能解释为用户逐项批准。

1. 选择输入保护作为第三轮有限范围，承接用户“继续优化”和此前委托诊断；若方向不合意，需调整这段前端交互。
2. 在当前功能分支内顺序实施，因前两轮未提交内容是依赖；若需独立提取第三轮，需使用保存的前后快照。
3. 暂留所有未提交计划的执行工作区，避免丢掉唯一的增量快照和日志；代价为少量被忽略的本地磁盘占用。
4. 加可选的首次创建回调及页面内草稿提交锁，以覆盖创建至 POST 的间隙和关闭重开；代价为一个额外可选参数和小型锁生命周期。
5. 提交前捕获页面上下文，防止等待创建期间导航改变原问题所指股票；代价为始终采用发送当时的上下文。
6. 不提供跨标签、跨设备或长期归档；若需要，需另外设计持久化层。
7. 刷新会丢失页面内待确认锁，且绝不自动重试 POST；未收到确认时，用户需核对会话记录后再决定重发。
8. 存储被浏览器拒绝时只保证页面内存恢复，不保证刷新；代价为这种环境刷新可能丢失未发送文字。
9. 后端接收/幂等保证和真实供应商执行不在本轮验证范围；如果存在集成问题，需要另外做后端或真实环境验证。
10. 用户其他修改和前两轮保留在本轮增量审查外；这些内容需要各自审查。
11. 独立审查者没有独立执行最终完整测试，最终命令由实现方执行读取；自动测试没有获得第二次独立执行的保证。
12. 最终整套下拉失败保留为待解决的验收问题，本轮不扩大修改仪表盘或共享下拉定位；代价为完整浏览器验收尚未全绿，偶发下拉操作问题仍需进一步定位。
