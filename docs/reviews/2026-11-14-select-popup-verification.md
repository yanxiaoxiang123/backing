# 下拉弹层越界修复验收

日期：2026-11-14

用户要求：修复剩余完整浏览器测试失败。沿用当前功能分支及未提交工作，仅修改前端，不启动后端或访问真实供应商。

## 故障与原因

此前两次完整运行分别在股票管理的“上海”选项和仪表盘的“万科A”选项点击时失败。两者都显示选项位于视口外，单独重跑原文件均通过。

重复缩放、开合仪表盘下拉的浏览器诊断复现了真实点击失败。采样记录显示，正常宽度 150px 的弹层短暂经过 `scale(0.0102201)`，随后宽度变为 15000px，横坐标约为 -707972px。页面没有滚动。

共享样式 `surfaces.css` 通过 `!important` 强制所有弹层过渡 `opacity, transform`。AntD 的 rc-motion 在开始阶段设置内联 `transition: none`，让 rc-trigger 测量位置；该设置被共享样式覆盖。AntD 在准备阶段使用 `scale(1)`、开始阶段使用 `scale(0)`，意外的 CSS 过渡产生接近零的比例。rc-trigger 根据变换后的边界计算缩放比例，再除以该值修正宽度及偏移，导致异常放大和越界。

第一次受控实验只移除共享过渡声明的 `!important`，诊断用例及原有股票管理、走势回归共 11/11 通过。后续收敛到保留时长与曲线，仅让 `transition-property` 尊重组件的内联禁用设置。
