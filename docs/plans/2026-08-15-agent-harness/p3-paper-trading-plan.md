> 日期：2026-08-15
> 依赖：规格 `docs/specs/2026-08-15-agent-harness-runtime.md`、总览 `00-overview.md`
> 状态：仅规划。本轮不实现；验收需 4–8 周连续运行验证，故作为后续会话的独立工程。

## 目标与边界

模拟盘是「研究 → 回测 → 审计 → 风控 → 人工批准 → 模拟执行 → 归因」闭环的可执行层。硬约束：

- Agent 只能提议订单（`execution.paper.propose`），订单必须经确定性风控校验 + 人工审批后才进入模拟盘。
- 每笔模拟订单可重放并解释（订单事件 append-only，关联 run_id/step/tool_call/approval）。
- 不引入实盘券商接口；不把模拟盘当作收益承诺。

## 依赖与顺序

P3-1（broker）与 P3-2（审批）是骨架；P3-3/P3-4 依赖它们；P3-5 是收口验证。所有切片建立在本轮 P0–P2 的 `approvals` 表、`tool_calls` 事实层、SSE 事件流与权限分级之上。

## 明确不做

- 实盘连接（P4 单独立项）；保证金/两融/期权；T+0 或非 A 股规则；自动执行（无审批不下单）。
