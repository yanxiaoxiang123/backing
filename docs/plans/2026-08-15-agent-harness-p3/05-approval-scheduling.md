# 05 审批状态机 + 撮合调度 + soak 循环

**交付**：订单审批卡（方向/目标仓位/触发条件/风险摘要/有效期）+ 审批状态机（一次性窗口）；每日撮合调度 API；后台 soak 循环。

**范围**：
- 状态机：`pending → approved/rejected`；批准后仅对下一个撮合窗口有效：成交 → `used`，窗口过 → `expired`；拒绝/过期/失效订单不得成交；再下单需重新审批。
- 调度：撮合循环以已同步日线为价格基准，处理"审批通过且窗口未过"的订单；提供手动触发撮合的 API（便于验收与 demo）。
- soak 循环：后台常驻任务周期性检查新日线并撮合（可配置间隔）；进程内/外均可运行（线程模式与既有 task 约定一致）。
- 审批卡 UI：前端 ApprovalCard 扩展订单字段（方向/数量/限价/风险摘要/有效期），批准/拒绝动作接审批 API。

**验收**：
- pytest：状态机全路径（含 used/expired）、无审批不成交、窗口一次性语义。
- 前端：Vitest 审批卡渲染与批准/拒绝交互；`npm run build` 全绿。
- 手动：工作台对一笔提议订单批准后，下一交易日撮合成交可见。

**阻塞**：03, 04
**委派**：ineligible（状态机+调度+API 耦合）
