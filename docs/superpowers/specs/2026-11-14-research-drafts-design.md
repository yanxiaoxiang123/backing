# 第三轮：研究输入保护

日期：2026-11-14

## 意图与授权

用户在两轮连续性优化后要求“继续优化”，此前已将具体体验问题诊断交由实现方判断。本轮由实现方选定输入保护这一有限前端范围，继续本会话实施；下面的取舍不是用户逐项确认。

## 用户应得到的行为

1. 未发送的文字随当前会话保存；没有会话时按合法股票保存，无股票则使用新研究草稿。同一浏览器标签页中，关闭副驾驶、切页、刷新和进入完整工作台均可恢复。
2. 会话优先于股票作为草稿身份；不同会话和不同未建会话的股票互不覆盖。副驾驶与工作台共用相同身份的草稿。
3. 已保存草稿（包括用户主动清空）优先于 URL prompt、股票预填和稍晚到达的会话数据。欢迎页问题仍由用户点击填入。
4. 输入不会通过 URL、服务端草稿接口或分析请求自动传输；只有点击发送/有效 Enter 才提交。中文输入法组合期间 Enter 不发送，Shift+Enter 换行。
5. 提交期间显示发送反馈并阻止重复提交；仅服务端确认接收后清空该次输入。明确拒绝、创建失败或运行时不可用保留原文供用户重试，不自动重试 POST。
6. 首次发送可能先创建会话再提交失败；该文字迁入刚创建的会话草稿，刷新仍可继续。旧请求完成不得清空其他会话或用户后来修改的草稿。
7. sessionStorage 不可用时仍可正常编辑和发送，在当前页面进程保留草稿；此时不保证刷新恢复。草稿与当前标签页生命周期一致，不承诺跨设备、跨标签或长期归档。
8. 已有会话的详情尚未恢复成功时，草稿仍可编辑，提交等待该身份加载成功，避免误建新会话。普通 HTTP 环境缺少 UUID API 也可编辑和发送，草稿版本使用页面内唯一降级值。

## 实现选择

- 复用 ChatInput，新增可选受控 value/onChange 和异步确认；通用组件不读取研究上下文。
- 增加 ResearchChatInput 适配组件及小型 sessionStorage 草稿存储，使用 useSyncExternalStore 同步当前页面中的读写。存储字符串与显式空值，损坏值安全回退，不影响其他 sessionStorage 数据。
- useAgentChat.send 返回 { accepted, threadId }，并提供首次创建会话的同步回调：在新身份展示前迁移草稿。提交前捕获页面上下文；服务端接收后即返回 accepted=true，即使用户已经换会话，仍只用版本保护可见状态更新。成功只代表提交已接收，分析生成失败仍在已保存会话显示。
- 进行中的提交按草稿身份在页面内共享锁；关闭重开副驾驶仍禁止重复提交。锁不持久化到 sessionStorage，刷新后不自动重试，若刷新中断了确认，应由用户核对会话记录后决定是否重发。
- 按新会话/股票/会话身份管理，首次创建后失败的迁移只移动未改变的源草稿且不覆盖已有目标草稿。
- 保留现有初始提示与欢迎操作、错误展示、SSE 和研究导航行为。不增加依赖或新的视觉体系。

## 验收与边界

单元测试覆盖存储损坏/不可用、身份隔离、条件清空与迁移、异步发送失败/成功/重复发送、输入法；hook 覆盖实际提交确认结果。Playwright 使用现有确定性 API 夹具覆盖关闭重开、刷新、交接、切换会话和首次提交失败恢复，并断言导航不产生 POST。

本轮只改前端，不新增后端草稿服务、任务中心或模型上下文；不调用真实模型、行情供应商或订单接口。保留前两轮及用户其他未提交工作，在当前功能分支实施，不提交、推送或部署。临时预览结束后停止。
