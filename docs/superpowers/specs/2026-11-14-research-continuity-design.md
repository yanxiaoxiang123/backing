# 单股研究连续性优化

日期：2026-11-14

## 授权与目标

用户在阅读体验诊断后表示：“可以，先按这个方向优化”。已同意的方向是：选中一只股票后，能够连续完成研究、回测，并在切页后继续工作。本文件细化该范围内的行为和工程约束，不扩展为全面改版。

目标：减少重复选择、重复寻找和切页后的工作中断。验收以真实操作链路为单位。

## 本轮范围

1. 修复策略页入口股票覆盖用户后续选择的问题。
2. 仪表盘具体报告链接直达报告详情，并支持刷新、关闭与浏览器返回。
3. 保留策略编辑草稿、最近一次回测及结果页签，支持切页和刷新后继续。
4. 回测完成优先展示绩效；旧结果明确标记对应运行，提供恢复原配置和历史记录入口。

不增加研究项目数据库、全局任务中心、实盘交易、模型调用、数据提供商调用或新的依赖。不更换现有 UI 风格。本轮不处理后台长任务的跨页恢复。

## 已有基础

- React Router、TanStack Query、AntD。
- `usePersistedState` 将当前标签页的非敏感配置写入 sessionStorage，存储异常不影响当前页面内存态。
- 个股详情已经以 `?stock=` 向工作台和策略页传递标的。
- `/history?result=<id>` 已支持定位已保存回测。
- 分析详情查询已有读取接口与加载、失败、重试界面。

## 设计决定（由实现方选择）

以下为采用现有栈的默认实现选择，不描述为用户逐项指定。

### A. 股票选择与 URL

- 策略页有效 `stock` URL 参数用于当前页面标的；无有效参数时恢复当前标签页的上次选择。
- 用户选择股票时同步更新 sessionStorage 草稿和 URL 的 `stock`，使用 replace，避免每次选择产生一条浏览历史。
- 清空选择删除 URL 的 `stock` 并清空草稿。
- 浏览器返回或外部链接改变有效 URL 标的时，表单随 URL 更新。
- 不在每次表单变化时重复用旧入口值覆盖选择。
- 新标的行情未到时，不把旧标的 K 线放在新标的下展示。

### B. 报告直达

- 使用 `/agent?report=<正整数 id>` 表示打开已保存报告详情。
- 仪表盘“打开分析报告”和每条最近分析带相应 ID。
- 报告列表“查看”也更新 `report`，页面以 URL 为详情打开状态的来源。
- 关闭详情只删除 `report`，保留其他查询参数，使用 replace。后退/前进由 URL 驱动，不能留下陈旧详情。
- 非法 ID 不发送详情请求，保留正常列表。
- 详情不依赖该记录出现在历史列表当前页。
- 详情加载、错误与重试沿用现有组件，查询 key 必须包含 ID，切换记录不能展示前一条的正文。

### C. 策略编辑草稿

- 股票、策略、时间、资金与执行假设沿用现有 sessionStorage 字段。
- 策略参数按策略名称分别保存：切换到另一策略用该策略草稿或默认参数，切回原策略恢复编辑值。
- 目录首次加载或后台刷新不重置用户参数。
- 默认参数从当前目录获得，只合并属于该策略且类型合适的保存值。
- 不把认证信息或密钥放入持久状态。

### D. 最近回测和结果查看位置

- 当前标签页只保留最近一次策略回测：原始回测响应及对应请求快照（股票、策略、参数、区间、资金、执行假设）。
- 使用独立版本标记与合理的结构校验；不合法的保存内容按不存在处理。
- 切页与刷新后恢复最近回测及结果页签，不自动再次 POST 回测。
- sessionStorage 中只保留一份最近回测，不累积完整历史；数据库仍是长期历史的来源。
- 浏览器存储不可用时，当前页仍能正常使用；不能承诺跨标签页、跨设备或关闭标签页后的恢复。
- 回测成功后自动选中“绩效指标”；生成信号后选中“行情与信号”，保留最近回测供后续查看。
- 资金曲线、绩效、交易记录始终标明属于哪次已保存运行；表单修改不会改写原运行。
- 是否“当前配置已调整”通过请求快照与当前完整配置比较，包括参数与执行假设。
- 行情图只叠加与当前完整配置一致的回测交易；旧结果可在独立结果页签查看。
- “恢复本次配置”从保存请求恢复表单与 URL，使用实际请求快照，不推断未知执行假设。
- “查看历史”进入现有 `/history?result=<id>`。
- 不持久化瞬时加载状态和进行中的请求；刷新不会伪造仍在运行。

## 用户流程

1. 自选/仪表盘打开股票详情，进入策略验证，自动带入股票。
2. 可改选另一股票，表单、URL 和随后提交一致。
3. 修改参数并回测，成功后直接看到该次绩效。
4. 查看历史再返回策略页，草稿和上次结果仍在。
5. 若编辑过配置，结果提示“当前配置已调整”；可恢复原运行配置或重新回测。
6. 从仪表盘打开最近分析，直接看到对应报告详情；刷新仍为同一份，关闭回到列表。

## 验证

- Playwright 回归：带入股票后改选成功，URL/提交值一致，清空可用。
- 回归：自定义策略参数在切换策略、目录刷新、切页、刷新后保留。
- 回归：回测后自动显示绩效；切页/刷新恢复；恢复不再提交回测。
- 回归：变更执行假设触发旧结果提示，恢复原配置可以继续。
- 回归：从仪表盘打开正确 ID；报告 URL 刷新、切换、关闭、无效参数与错误重试正确。
- 单元测试验证参数合并、保存数据校验与请求比较等非平凡状态规则。
- 前端 typecheck、lint、构建、单元测试与相关 e2e；格式检查以本轮文件为基础，同时说明原有全仓问题。
- 本地浏览器用确定性测试夹具查看工作流，不调用真实模型或执行模拟订单。

## 实现组织

- 策略恢复与报告直达可在不同文件集并行实施；最终在同一分支中统一验证。
- 保留当前分支和用户已有未提交改动；不提交、不推送、不部署。
- 完成后报告实际修改、验证结果与恢复范围。
