# Agent 工作台：股票查找与连续研究改进

日期：2026-10-30
状态：用户已确认六项范围，实施中。

## 目的与需求来源

用户在 Agent 工作台输入 `000001.sz`，希望系统自动查询规范代码 `sz.000001`，并补齐 Agent 功能。用户明确要求使用 Superpowers 完整流程。

本轮建议围绕「查找股票 → 获取证据 → 连续追问 → 发起研究」完成一个可验收的闭环。除代码后缀转换外，下述新增功能是实施方根据现有系统提出的建议，尚未视为用户确认。

## 已确认的问题

通过当前代码及本地无网络复现确认：

- `backend/app/domain/stock_codes.py` 的直接解析仅接受交易所前缀和六位裸代码；`normalize_stock_code('000001.sz')` 抛出 StockCodeError。
- 自由文本提取只消耗后缀代码的六位数字，`canonicalize_stock_code_in_text('000001.sz')` 得到错误字符串 `sz.000001.sz`；`000001.sh` 还可能被错误推断为深圳。
- `TurnToolPolicy.classify('000001.sz')` 与规范代码单独输入都返回 NONE，不向模型开放查询工具。
- 原生聊天只开放行情、K 线、基础信息和财报四个只读工具；已存在的新闻、公告工具没有开放。
- 历史目标提取取整个历史的首次匹配，切换股票后的追问可能沿用旧标的；页面上下文仅作为提示词附加，并未参与工具准入和目标决策。
- 工作台右侧股票由研究 run 或 URL 推导，普通聊天查股无法直接切换右侧行情。

当前工作树已有大量未提交变更，包括聊天 runtime、service、前端会话组件；实施时保留现有变更，不重置工作树，不自动提交。

## 目标行为

### 1. 股票代码统一识别

前后端共同支持下列输入，并输出内部规范形式：

| 输入 | 规范结果 |
| --- | --- |
| `000001.sz`、`000001.SZ`、`SZ.000001`、`sz000001`、`000001` | `sz.000001` |
| `600000.sh`、`SH600000`、`sh.600000` | `sh.600000` |
| `430047.bj`、`BJ430047` | `bj.430047` |

明确写出的交易所具有优先级，不先剥离为裸代码再推断。例如 `000001.sh` 必须保留为 `sh.000001`，不得悄悄改为深圳股票；是否属于股票由后续数据查询验证，不把指数当作股票基础信息返回。

保留现有合法代码的兼容行为；本轮不扩大裸代码的市场推断规则。自由文本必须完整消耗代码后缀；避免从长数字、英文标识符、带非法后缀的 token 中截取一个看似合法的股票代码。中文句子中紧邻代码的写法应正常识别。

### 2. 单独输入代码即可查询

在工作台发送 `000001.sz`，自动把本轮判为只读查询，并使用规范代码执行基础信息查询及最新行情快照。无需用户补充「查询」等动词，也无需模型自行决定是否执行最基本的查询。

工具调用和结果沿用现有事件协议，展示在会话中。随后模型根据实际工具结果解释股票身份和可用行情，并明确来源、时间、缓存陈旧状态及失败或缺失的数据。只输入代码不创建量化研究 run。

模型看到的当前目标和工具参数使用规范代码；数据库保存的用户原始输入与聊天气泡保持原样。

### 3. 股票名称搜索

新增一个通过 typed tool gateway 调用的只读股票搜索工具（建议 `market.search`，模型别名 `market_search`），查询现有 Stock 表，支持代码的各类受支持写法、股票全名和名称片段。结果数量有上限，稳定排序，SQL 参数化；名称中的 `%`、`_` 按普通字符处理。

明确代码按精确规范代码搜索；名称先精确匹配，再返回有限的名称包含匹配。搜索不触发联网同步或修改自选股。

对「搜索平安银行」「查询平安银行」这类明确查找请求开放搜索工具；单独输入名称时模型可使用搜索工具判断是否为已收录股票，问候、能力询问仍优先保持无工具。只返回一个候选时可继续查询该股；多个候选时列出名称与代码让用户选定，不自动挑第一只；零结果明确说明当前股票库未收录或未匹配。

本轮名称识别不涵盖拼音、别名、行业筛选及全市场远端搜索。多个股票比较不在本轮范围；遇到多个明确目标时要求用户先选定本次查询/研究股票，不能悄悄丢弃其余目标。

### 4. 连续追问与上下文

股票目标优先级：本轮用户明确代码或本轮搜索唯一匹配结果 → 当前会话最近一次明确确认的股票 → 有效的股票页面上下文。

历史目标从最近向前查找，并基于用户输入及明确的成功股票搜索/查找结果建立；不能从助手任意叙述、新闻正文或失败查询里猜目标。多结果搜索不是目标确认。用户切换股票后，「查看财报」「最近有什么新闻」「分析一下」「回测均线策略」应沿用新股票。新会话不得继承旧会话的聊天目标；切换已有会话时恢复该会话目标。

行情、财报、新闻、公告等只读请求不创建研究 run；明确分析、策略与回测请求才走现有量化 run，继续保留取消、权限、幂等及 run.linked 行为。没有可靠股票目标时可以先用名称搜索解析；仍缺目标则追问，不能擅自分析某只股票。

### 5. 开放现有新闻与公告工具

把已有 `event.news`、`event.announcement` 纳入聊天只读工具映射和执行 allowlist。加入新闻、公告、财务报表、股票搜索等常见中文查询表达的意图识别。

通过 DEFAULT_REGISTRY 执行，不直接访问供应商；沿用结果 envelope、审计及来源时间。没有新闻、公告或供应商不可用时明确解释，不编造消息、不用失败结果支撑投资结论。

### 6. 右侧行情跟随当前股票

右侧行情优先展示当前会话最新明确查询/选定的股票；没有会话目标时才回退到当前会话关联 run 的目标或 URL 股票。查询新股票后，即使旧 run 仍显示为历史研究，行情也应切换到新目标，界面明确标出行情股票，避免与旧研究结论混淆。

会话切换时清理上一会话 run/行情的展示归属，防止串会话；新股票行情加载时清除旧行情，网络请求竞态不能回写旧股票图表。沿用现有组件与样式，不重做整体视觉布局。

普通查询通过现有聊天事件/恢复路径携带或推导规范股票身份，避免让前端解析助手自然语言判断目标。若现有 ToolRow 信息不足，可添加可选的规范股票目标字段，并保持旧事件兼容；无需新增数据库表，目标可由会话输入及工具事件重建。

## 独立设计检查后的实施方决定

以下为实施方补充的确定行为，随本设计一并供用户确认：

- 名称搜索先查精确名称，存在精确结果时仅返回精确结果；没有精确结果才进行包含查询。股票名称按数据库收录内容匹配，不做模糊别名猜测。
- 当前轮明确指定新目标但无法解析、零命中或存在多个候选时，停止该目标的后续查询/研究并说明原因，不回退到历史股票或页面目标；会话之前的已确认目标可以保留，但不能用于回答本轮新目标的问题。
- 运行时先完成目标解析，再决定本轮后续工具权限。名称唯一命中后，运行时建立本轮规范目标；普通名称查询自动执行基本信息和行情查询。带有明确分析/回测意图的名称请求只在唯一目标确认后自动创建一次现有研究 run。歧义或零结果时不开放或执行 quant_run_analysis；模型不能自行绕过这一守卫。
- 多目标检查在运行时的目标解析层执行。代码通过共享解析器收集当前消息所有完整引用，规范化并去重；多于一个不同代码即要求选择。本轮检索名称是单个查询字符串，不解析任意自然语言里的所有公司名；遇到明确比较/多目标表达，或股票搜索返回多个候选，同样要求选择，不创建研究 run。代码与同一公司的名称共同出现不当作两个目标。
- 明确代码必须先在 Stock 表成功找到对应股票，才自动查行情、确认会话目标或启动股票研究。对 `000001.sh` 规范化保留 `sh.000001`，股票库不含对应股票时说明未收录或不是可研究的股票，不改查深圳、不展示指数行情、不启动财报/新闻/股票研究。本轮不新增指数研究能力。
- 有效股票页面上下文需同时满足 entity_type 为 stock、entity_id 能规范化且在 Stock 表存在；它只在用户没有指定新目标且会话没有已确认股票时补足目标。
- 前端将规范代码作为身份传递，未知/错误代码不能从文本部分匹配成另一股票；行情与研究任务分别标注所属股票。

## 技术约束与实施方选择

- 沿用 FastAPI、SQLAlchemy、Pydantic、React、TypeScript 和现有 DeepSeek 原生聊天运行时，不切换模型供应商，不引入外部 harness。
- 共享的股票代码层是规范化唯一来源，前端 utility 实现相同接受规则；显式交易所不受裸代码推断覆盖。
- 新工具只读、有限结果、输入校验，所有数据经过 typed gateway。禁止开放写入/模拟下单/宿主代码执行权限。
- 不引入迁移或自动股票同步；本地股票库缺数据需如实报告。
- 不增加自动重试产生重复研究 run；沿用任务与聊天生命周期。
- 确保模型工具名符合现有下划线命名约定，注册表保留点分域名。
- 具体目标重建 helper、可选事件字段命名和搜索条数由实施者选择，保持向后兼容。

## 非目标

本轮不承诺把 Agent 做成覆盖所有投资任务的系统；不新增实时交易、不扩建多 Agent 架构、不添加联网任意网页搜索、策略自动优化器、持仓自主调整或模型配置重构。上述能力可单独规划。
